# NPS 网络嗅探器操作演示视频介绍稿

> 用途：配合屏幕录制使用的旁白稿与分镜说明。
> 建议成片 7 分钟左右，旁白约 1,500 字，语速 200–220 字/分钟。
> 操作步骤与 `docs/DEMO.md` 一致，本稿侧重"边操作边讲解"的口语化表达。

## 一、录制参数

| 项目 | 建议 |
| --- | --- |
| 画面 | 1920×1080，只录应用窗口，不录任务栏与通知 |
| 环境 | Npcap 已安装；Wi-Fi 或回环网卡可用；浏览器提前打开一个 HTTPS 页面 |
| 流量 | 抓包开始后访问 2–3 个网站，保证有 TLS 握手与多条会话 |
| 鼠标 | 移动放慢，每次点击后停 1 秒，方便观众跟上 |
| 隐私 | 不展示真实账号、Cookie、聊天内容；演示站点用 example.com 等公开地址 |
| 分段 | 按下面的分镜分段录制，口误只重录当段，后期拼接 |

## 二、分镜与旁白

### 1. 开场（0:00–0:25）

**画面/操作**：主窗口已打开，停在空列表状态，鼠标不操作。

**演示重点**：先讲清楚"这是什么、能做什么、不能做什么"。

**典型场景**：网络排障、协议教学、自有应用验证、授权范围内的安全自查。

**旁白**：

> 大家好，今天演示的是 NPS 网络嗅探器。它是一款面向授权网络诊断和教学场景的轻量抓包工具，可以实时抓包、解析协议、跟踪会话、识别应用，在 Windows 上还能把连接归属到具体进程。
>
> 先说明边界：请只在自有网络或者获得授权的环境里使用；它不提供 TLS 解密，也不会上传任何流量数据。

### 2. 界面总览（0:25–1:05）

**画面/操作**：鼠标依次划过左侧包列表、中间详情树与十六进制、右侧三个页签、顶部工具栏、底部状态栏。

**演示重点**：让观众建立"三窗格 + 页签 + 状态栏"的空间感。

**旁白**：

> 先看界面。主窗口分成三块：左边是包列表，中间上方是协议详情树，下方是十六进制；右边是三个页签，分别是会话、统计和流时序图。
>
> 顶部工具栏用来选网卡、填捕获过滤器；下面这一行是显示过滤器；最底下的状态栏会显示包数、队列长度和丢弃计数，抓包时盯这里就能判断有没有跟不上流量。

### 3. 选择网卡与捕获过滤（1:05–1:50）

**画面/操作**：点开「接口」下拉框，展示可读设备名；选择 `Intel(R) Wi-Fi 6 AX201 160MHz`；在「捕获过滤器」输入 `tcp or udp`；点「开始」。

**演示重点**：设备名已经做过可读化处理；BPF 是内核层过滤，和显示过滤不同。

**旁白**：

> 接口下拉框里现在是人类可读的设备名称，比如这块 Intel Wi-Fi 6 网卡；回环设备会显示成"回环抓包"，不会出现一串 GUID。
>
> 选好网卡，在捕获过滤器里输入 `tcp or udp`。这是 BPF 语法，由驱动在内核层过滤，只有符合条件的包才会送到我们程序里；它和后面的显示过滤不是一回事，捕获过滤会真的减少数据量。
>
> 点开始，抓包就启动了。

### 4. 抓包与包列表（1:50–2:35）

**画面/操作**：包列表快速滚动；打开浏览器访问一个 HTTPS 网站；鼠标指向 No.、时间、源、目的、协议、长度列；指向状态栏的队列/丢弃计数。

**演示重点**：实时性、列含义、丢弃计数的作用。

**旁白**：

> 包列表开始滚动了。第一列 No. 是全局帧序号，后面依次是时间、源地址、目的地址、协议和长度。
>
> 现在我访问一个网站，产生一些真实的 HTTPS 流量。可以看到 TCP 握手、TLS 握手和应用数据陆续出现。
>
> 抓包过程中留意右下角的队列和丢弃计数：如果丢弃一直涨，说明流量超过了处理速度，可以缩小捕获过滤范围，或者只抓某个端口。

### 5. 详情树与十六进制（2:35–3:25）

**画面/操作**：选中一个 TLS ClientHello 包；展开 `Ethernet → IPv4 → TCP → TLS`；找到 `Host Name`（SNI，有些资料写作 `server_name`）并点击；观察右侧十六进制高亮。

**演示重点**：字段偏移对齐；TLS 只能看到握手明文，应用数据是密文。

**旁白**：

> 选中一个 TLS 包，看中间的详情树。从以太网、IP、TCP 一层层展开，最后到 TLS。
>
> 在 TLS 里能看到 ClientHello 携带的 SNI，也就是客户端要访问的域名，还有支持的版本和加密套件。点一下 `Host Name`（有些资料里叫 `server_name`），右边的十六进制会高亮对应的字节，位置是完全对齐的。
>
> 这里要特别说明：我们能读到的是握手里的明文信息，握手之后的应用数据是加密的，工具不会去解密，这是它的安全边界。

### 6. 显示过滤（3:25–4:10）

**画面/操作**：在显示过滤器输入 `protocol == tls`，列表只剩 TLS；再输入 `ip.addr == 93.184.216.34 && tcp.port == 443`；最后故意输入 `ip.srcc == 1.2.3.4`，展示红色错误提示，上一条规则仍生效；清空恢复全部。

**演示重点**：语法能力、类型/字段校验、显示过滤不改变原始数据。

**旁白**：

> 接下来是显示过滤。输入 `protocol == tls`，列表就只剩 TLS 包；也可以写 `ip.addr == 某个地址 && tcp.port == 443`，支持与、或、非、括号和网段。
>
> 我故意写错一个字段名，比如 `ip.srcc`。可以看到下面给出红色提示，但上一条有效规则还在生效，界面不会被打乱。
>
> 显示过滤只影响"看不看得到"，不会删掉已经抓到的包，帧序号也保持不变，清空表达式就能恢复。

### 7. 会话追踪（4:10–4:55）

**画面/操作**：切到「会话」页签；展示会话行（五元组、上下行包数/字节、状态、进程列）；点击一条会话；观察包列表整条流高亮；再点另一条会话对比。

**演示重点**：双向流量合并、同流高亮、会话老化。

**旁白**：

> 切到会话页签。这里把同一个五元组的双向流量合并成一条会话，能看到上下行包数、字节数、TCP 状态和持续时间。
>
> 点一条会话，左边包列表会把整条流高亮出来，特别适合看一次请求和响应是怎么对应的。
>
> 会话有老化时间，长时间没有新包的会话会自动清理，避免列表无限增长；也可以在工具栏点清空重新开始。

### 8. 协议识别与 TLS 边界（4:55–5:35）

**画面/操作**：展示会话页签的协议列与置信度 tooltip；分别指出 HTTP、TLS、DNS、SSH 等会话；悬停查看"DPI 识别"或"端口推断"。

**演示重点**：DPI 在首个载荷后识别；置信度区分"内容匹配"和"端口猜测"。

**旁白**：

> 协议识别在首个载荷到达后进行，常见的有 HTTP、TLS、SSH、DNS、BitTorrent。识别结果会带置信度：`DPI` 表示内容特征匹配，`端口` 表示只是根据端口推断。
>
> 比如这条 443 的会话识别成 TLS，是因为看到了 TLS 握手的结构；如果只是端口像，但内容对不上，就会标成端口推断，避免给出过度确定的结论。
>
> 再强调一次，TLS 只解析握手，不碰加密正文。

### 9. 流时序图（5:35–6:15）

**画面/操作**：切到「流时序图」页签；选中一条包数较多的会话；滚轮缩放、拖动平移、双击复位；指出上下行颜色与包长数字。

**演示重点**：横轴时间、纵轴两端、方向箭头、密集聚合。

**旁白**：

> 切到流时序图。横轴是时间，上面是客户端、下面是服务端，每条线代表一个包，箭头指向接收方，旁边的数字是包长。
>
> 滚动滚轮可以以鼠标位置为中心缩放，按住拖动可以平移，双击或者按 0 复位。包很密的时候，工具会自动按像素列合并，十万个点也不会卡。
>
> 这个视图特别适合看握手往返、重传和请求响应的节奏。

### 10. 进程归属（6:15–6:55）

**画面/操作**：回到「会话」页签，指向「进程」列；悬停展示 tooltip（进程名、PID、置信度）；在显示过滤器输入 `process.name == "msedge.exe"`（或实际进程名）；再输入 `process.pid != 0` 只显示已归属会话。

**演示重点**：Windows 本机进程归属、置信度、代理场景的边界。

**旁白**：

> 这是 Windows 上的进程归属。会话列表的进程列会显示进程名和 PID，比如浏览器或者代理进程；鼠标悬停能看到归属依据：四元组精确匹配、仅端口推断，或者端口冲突。
>
> 也可以直接用 `process.name` 或者 `process.pid` 过滤，只看某个进程的流量。
>
> 有一个容易误解的地方：如果开了系统代理，物理网卡上看到的是代理进程的连接，浏览器到代理之间是回环流量，所以要抓回环或者关掉代理，才能看到浏览器本身。

### 11. 统计与导出（6:55–7:25）

**画面/操作**：切到「统计」页签，展示协议分布、Top 会话、吞吐时间线；回到包列表点「保存」；弹出授权/敏感信息确认，点确认；选择路径保存；用 Wireshark 打开导出文件展示包数一致（可选）。

**演示重点**：统计视图的排障价值；导出前的授权与隐私确认。

**旁白**：

> 统计页签有协议分布、Top 会话和吞吐时间线，排障时可以先看这里，快速判断是哪个协议、哪条流占了带宽。
>
> 最后演示导出。点保存，程序会先提示：请确认你有权导出这些流量，文件里可能包含账号、Cookie 等敏感信息。确认之后才写文件。
>
> 导出的 PCAP 可以用 Wireshark 打开复核，包数和这里是一致的。

### 12. 收尾（7:25–7:40）

**画面/操作**：回到主界面，鼠标停在状态栏，画面渐隐或静止。

**演示重点**：重申适用场景与安全边界。

**旁白**：

> 以上就是 NPS 的主要功能。它适合网络排障、协议教学、自有应用验证，以及授权范围内的安全自查。
>
> 再次提醒：只在授权环境使用，注意保护流量中的隐私信息。谢谢观看。

## 三、录制提示

1. **先准备流量**：浏览器提前打开两三个 HTTPS 页面，录制到"抓包"环节时再刷新，避免现场等待。
2. **每步留停顿**：点击后停 1 秒再讲下一句，后期剪辑有余量；口误按分镜重录，不必整段重来。
3. **鼠标不要抖**：移动路径尽量直线，点击前先停稳；需要强调的列用鼠标画圈或短暂悬停。
4. **避免敏感信息**：不要展示真实域名、账号、Cookie、聊天内容；必要时用 `example.com` 或本地测试服务。
5. **旁白与画面对齐**：讲到"点开始"时再点，讲到"高亮"时再点字段，观众更容易跟上。
6. **字幕**：建议把每段旁白作为字幕，专有名词保留英文（BPF、TLS、SNI、DPI、PID）。

## 五、旁白速查（提词版）

> 大家好，今天演示 NPS 网络嗅探器。它面向授权网络诊断和教学，能实时抓包、解析协议、跟踪会话、识别应用，并在 Windows 上把连接归属到进程。请只在自有或授权网络使用，它不提供 TLS 解密，也不上传数据。
>
> 界面分三块：左边包列表，中间详情树和十六进制，右边会话、统计、流时序图；顶部选网卡和捕获过滤器，底部状态栏看包数和丢弃。
>
> 选 Wi-Fi 网卡，捕获过滤器填 `tcp or udp`，开始抓包。访问一个网站，就能看到 TCP 和 TLS 握手。
>
> 选中 TLS 包，展开到 `Host Name`（SNI），右边十六进制会高亮域名对应的字节；这里只能看握手明文，应用数据是密文。
>
> 显示过滤器可以写 `protocol == tls` 或者 `ip.addr == ... && tcp.port == 443`；写错字段会提示，但上一条规则继续生效。
>
> 会话页签把双向流量合并成一条流，点击后整条流高亮；协议识别会标注 DPI 或端口推断。
>
> 流时序图看往返节奏，滚轮缩放、拖动平移、双击复位，密集时自动聚合。
>
> 进程列显示进程名和 PID，悬停看归属依据，也可以用 `process.name` 过滤；开代理时物理网卡看到的是代理进程。
>
> 统计页看协议分布和 Top 会话；导出前会确认授权和敏感信息。
>
> 以上就是主要功能，适合排障、教学和授权自查，注意保护隐私。谢谢观看。
